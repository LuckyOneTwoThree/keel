# 项目章程

> 基线文件 · L3 改基线需走 DEC- 留痕。
>
> **⚠️ 示例夹具项目**:本项目仅用于验证 PM-Playbook v3.0 协议可跑通,内含 2 条 DEC + 2 条 PRG + 1 条 RSK + 1 条 DEP + 1 条 COM 作夹具,**非真实业务数据**。真实项目请用 `pm init PROJ-你的项目名` 新建。

## 1. 项目定位

Node 是纯 Web3 Native 的自管钱包 App,含冷钱包舱 + 服务舱(福利/保险库/DID),并提供 B 端服务管理后台。从原"IM开放服务生态矩阵"中独立剥离。

## 2. 产品形态

- **C 端 App**:两大一级 Tab
  - 冷钱包舱(资产看板/Swap/Faucet/收发/钱包管理)
  - 服务舱(福利特权 3 模块 + 保险库 + 数字身份通行证 + DApp 探索)
- **B 端配套**:服务管理后台(服务注册/产品配置/合约链/参数/权益/审计/权限)
- **已剥离**:IM 聊天通讯 App、IM 开放服务统一后台(作为外部独立应用)

## 3. 当前阶段

原型收口期(整体约 90% 完成),余「团队」「交易」两模块收尾。

## 4. 技术栈

前端原型(HTML/Tailwind/JS),服务端(Java),Web3 钱包集成。

## 5. 关键决策依据

- DEC-0005:产品形态独立与边界确认
- DEC-0006:Aeon R9 集成 Node 架构(3 Tab 重组)
- DEC-0007:Node 商城 v2.0 层级化代理商城(已归档·被取代)
- DEC-0008:代理入口下沉与代理中心管理化(已归档·被取代)
- DEC-0009:代销批量方案与库存管理(已归档·被取代)

现行有效交易/商城设计以"统一商品池+级差返利"为准,详见 [REQ-0001-PRD](../文档库/01-需求/REQ-0001-PRD.md) §3。

## 6. 项目边界

- 本项目(PoC 克隆)只含 1 条 REQ + 5 条 DEC + 2 条 PRG + 1 条 RSK + 1 条 DEP + 1 条 COM 作夹具,验证 v3.0 协议可跑通
- 真实项目位于外部仓库,不在本 PoC 范围
