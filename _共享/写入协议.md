# 写入协议

> v3.0 · 与 `scripts/check.py` 强制层配套。改本文件 = L3 改基线。

## 1. 编号规范
- 格式:前缀-4 位序号,如 `REQ-0007`。
- 前缀:REQ / PRG / DEC / COM / KB / RSK / DEP / GKB。
- **作用域**:per-project(项目内独立递增),不共享序列;GKB 是 workspace 全局(_共享/ 下唯一)。
- 新编号 = 该类(本项目内)现有最大值 + 1。
- 跨项目引用语法:`REQ-0007@PROJ-灯塔`(@ 后是项目名);check.py 默认不校验跨项目(仅 `pm link-check --cross` opt-in 跑)。
- agent 不得编造编号。

## 2. frontmatter schema(对应 v3.0 §2.1)

> **A1 修法**:正文不重复 frontmatter 字段。字段全部在 frontmatter,正文只放散文。
>
> 分两类:**条目级**(参与编号唯一性校验,必有 id)和**文档级**(type: doc,不参与唯一性校验,用 ref 关联 REQ)。

### 2.1 条目级 schema(REQ/PRG/DEC/COM/KB/RSK/DEP/GKB)

```yaml
---
id: REQ-0007              # 必填,编号(同类型全局唯一)
type: req                 # 必填,枚举:req/prg/dec/com/kb/rsk/dep/gkb
title: 一句话标题           # 必填
date: 2026-07-25          # 必填,ISO YYYY-MM-DD
status: 待评审             # 必填,见 §3 状态枚举
scope: 在范围              # req 专用:在范围 / 明确不做
related: [DEC-0012, RSK-0003]  # 项目内引用,check.py 校验悬空(draft:false 时硬阻断)
related_external: []      # 外部引用(裸字符串或 @PROJ 语法),不校验
draft: false              # 默认 false;true = 未定稿,宽松校验(见 §4)
review_due: 2026-10-25    # dec/rsk 必填,ISO 日期,复审到期(check.py 强制)
confirmed_by: PM          # 可选,L2 写入时填
proj_id: PROJ-X           # 可选,文件级标识(pm init 自动补)
artifacts: [01-需求/REQ-0007-PRD.md]  # req 专用:关联文档库产物路径(相对 文档库/)
---
```

**类型特定字段**:

| 类型 | 必填字段 | 可选字段 |
| --- | --- | --- |
| REQ | id/type/title/date/status | scope, artifacts, related, related_external, draft, confirmed_by, proj_id |
| PRG | id/type/title/date/status | related, related_external, draft, confirmed_by, proj_id |
| DEC | id/type/title/date/status, **review_due** | related, related_external, draft, confirmed_by, proj_id |
| COM | id/type/title/date/status | stakeholder, channel, participants, related, related_external, draft, confirmed_by, proj_id |
| KB | id/type/title/date/status | category(踩坑/经验/方法), related, related_external, draft, confirmed_by, proj_id |
| RSK | id/type/title/date/status, **level**, **review_due** | probability, impact, owner, mitigation, related, related_external, draft, confirmed_by, proj_id |
| DEP | id/type/title/date/status, **expected_delivery** | owner, partner, blocks, related, related_external, draft, confirmed_by, proj_id |
| GKB | id/type/title/date/status | domain, source, related, related_external, draft, confirmed_by |

**枚举校验**(check.py 强制):

| 字段 | 允许值 |
| --- | --- |
| `level` (rsk) | 高 / 中 / 低 |
| `scope` (req) | 在范围 / 明确不做 |
| `category` (kb) | 踩坑 / 经验 / 方法(参考,check.py 未强制) |
| `domain` (gkb) | 需求 / 评审 / 交付 / 风险 / 协作 …(参考,check.py 未强制) |

**文件位置校验**(check.py 强制):

| 类型 | 必须位于 |
| --- | --- |
| RSK | `项目管理/风险登记册.md` |
| DEP | `项目管理/依赖登记册.md` |
| REQ(条目) | `项目管理/需求登记册.md` |
| 其他 | 任意(按路由表推荐) |

正文结构:
```markdown
### 编号 — YYYY-MM-DD
标题

(散文:背景/描述/影响/理由 等)
```

### 2.2 文档级 schema(type: doc)

> doc 文件**不参与编号唯一性校验**(无 id),用 `ref` 关联 REQ-XXXX。
> 条目级元信息(id/status/scope/related)在 `项目管理/需求登记册.md`,doc 文件只放详情。

```yaml
---
type: doc                 # 必填,固定 doc
subtype: prd              # 必填,枚举:prd/plan/research/review/acceptance/report
title: 文档标题            # 必填
date: 2026-07-25          # 必填,ISO YYYY-MM-DD
ref: REQ-0007             # 必填(报告除外),关联的需求编号
related: []               # 文档级关联(可选,如引用 DEC)
related_external: []
draft: true               # 默认 true
proj_id: PROJ-X           # 可选
---
```

**subtype 枚举**(check.py 强制):

| subtype | 用途 | 命名规范 | 位置 |
| --- | --- | --- | --- |
| prd | 需求文档 | `REQ-XXXX-PRD.md` | `文档库/01-需求/` |
| research | 调研报告 | `REQ-XXXX-调研.md` | `文档库/02-调研/` |
| plan | 方案文档 | `REQ-XXXX-方案.md` | `文档库/03-方案/` |
| review | 评审记录 | `REQ-XXXX-评审.md` | `文档库/04-评审/` |
| acceptance | 验收报告 | `REQ-XXXX-验收.md` | `文档库/05-验收/` |
| report | 周报/阶段报告 | `YYYY-MM-DD-周报.md` | `文档库/07-报告/` |

**报告类(report)特殊处理**:`derived: true` 标记(PM 确认后从 `.draft/` 落入 `07-报告/`,真相源但豁免条目扫描)。

## 3. 状态枚举(check.py 强制)

| 类型 | 允许状态 |
| --- | --- |
| REQ | 待评审 / 开发中 / 已验收 / 已砍 |
| PRG | 进行中 / 已完成 / 已阻塞 |
| DEC | 评估中 / 生效 / 待复审 |
| COM | 已对齐 / 待跟进 / 失效 |
| KB | 本地 / 已晋升→GKB-XXXX / 过时 |
| RSK | 开放 / 已缓解 / 已关闭 |
| DEP | 等待中 / 已就绪 / 已逾期 |
| GKB | 生效 / 已归档 |

**通用例外状态**(所有类型均可追加):
- `已作废(PM拒绝)` — agent 写入被 PM 拒绝
- `已作废(误)→DEC-0014` — 写错了,指向正确条目

不计入"活跃条目"过滤。

## 4. draft 宽松位(D1/D2 修法)

- `draft: true`:未定稿,check.py 只校 id/date/type/title 格式,**悬空引用/必填缺失降级为警告**。
- `draft: false`(默认):定稿,全校验。
- **draft 绑"引用/字段完整度",与作者身份正交**——agent 写的、PM 已确认的、但含前向引用(等引用落地)的条目,照样该 draft:true。
- PM 新建默认 draft:true;agent 落真相源(L2 已过 PM 确认)默认 draft:false(除非含前向引用)。
- 定稿 = `pm finalize <id>`(draft:true → false + 跑全校验)。
- **forcing function**:`pm check` 报"N 条草稿超 7 天未定稿";超 14 天升为阻断(强制 finalize 或砍)。

## 5. 编号分配流程

```
PM: "加一条需求,关于 X"
agent:
  1. grep 项目内 REQ- 取最大值 → 候选 = max+1
  2. 输出草稿(含提议编号 REQ-XXXX,draft:true)
  3. PM 确认编号 + 内容
  4. agent 写入真相源 + commit(写前二次校验最大值,防 TOCTOU)
  5. commit message: [REQ-0007] 新增需求\n\nApproved-by: PM
```

PM 自写可跳过步骤 1-3,直接 `pm new-req "标题"` → 编辑 → `pm finalize` → `pm commit`。

## 6. commit 规范(v3.0 §2.2)

- **一条条目 = 一个 commit**(单条目状态变更不得跨 commit)。
- 格式:
  ```
  [<编号>] <动作短语>

  Approved-by: PM        # L2/L3 写入必带;PM 自写可省
  Reviewed-by: agent     # 可选
  ```
- agent 写盘即 commit(不许批量积压);pre-commit hook 调 check.py,失败则拒绝 commit。
- 派生文件冲突 = 重跑派生,不必上锁。
- 基线文件冲突 = 走 L3 确认门串行化,天然不冲突。

## 7. 勘误模式(append-only 下纠错)

> agent 写错了不能删。新增条目状态标"作废→指向正确条目"。

```yaml
---
id: DEC-0013
status: 已作废(误)→DEC-0014
date: 2026-07-25
---
```
正文保留原内容,不删。这是只追加原则的标准应用。

**PM 拒绝 agent 写入后**(基本回滚):不 git revert(条目会消失,审计要靠 git log 才能还原),改为**保留条目 + 改状态为 `已作废(PM拒绝)` + 新 commit**。markdown 自身即审计层。

**禁止**:`git reset --hard`、`git push --force`、手工删行、`git revert`(除非 PM 显式要求且接受审计层迁移到 git log)。

## 8. 冲突处理

- **append-only 日志(不同条目)**:git 干净 merge,无冲突。
- **同一条目状态字段变更**:靠 L2 确认门串行化 + 单条目单 commit。
- **派生文件(现状/INDEX)**:"最后写入者胜"是 OK 的,因为可重建;冲突时重跑派生。
- **基线文件(章程/登记册范围/路线图里程碑)**:走 L3 确认门串行化。

## 9. 日期与排序
- 全部用 ISO YYYY-MM-DD(高频日志可补 `时:分` 到 SESSION- 编号,不进 frontmatter)。
- 同文件内倒序(最新在顶)。
- 历史回填时编号与时间可能冲突(编号小但时间新)——check.py 仅警告,不强约束。

## 10. 分片规范(可选)
- 默认单文件;仅当超 200 行或 50 条时按月分片 `xxx-YYYY-MM.md`,旧月滚入项目内 `归档/`。
- `记忆/agent会话.md` 也走此规则。

## 11. 文档库与原型命名

**阶段产出(01-05)**:文件名 = `REQ-XXXX-{类型}.md`,frontmatter 必须含 `type: doc, subtype: ...`。

| 目录 | subtype | 文件名格式 |
| --- | --- | --- |
| `01-需求/` | prd | `REQ-XXXX-PRD.md` |
| `02-调研/` | research | `REQ-XXXX-调研.md` |
| `03-方案/` | plan | `REQ-XXXX-方案.md` |
| `04-评审/` | review | `REQ-XXXX-评审.md` |
| `05-验收/` | acceptance | `REQ-XXXX-验收.md` |

**周期记录(06-07)**:文件名 = `YYYY-MM-DD-{主题}.md`,持续累加。

| 目录 | subtype | 文件名格式 |
| --- | --- | --- |
| `06-会议/` | deferred(设计方案 v3.0 §七,不预建模板,现写现用) | `YYYY-MM-DD-会议-{主题}.md` |
| `07-报告/` | report | `YYYY-MM-DD-周报.md` / `YYYY-MM-DD-阶段报告.md` |

**原型目录**:`原型/REQ-XXXX-vN/`,vN = 版本号(从 v1 起递增)。路线图/现状引用本目录下的 HTML/原型包。

**草稿区**:`.draft/draft-{意图}.md`(幂等键从意图派生,见 `.draft/README.md`)。
