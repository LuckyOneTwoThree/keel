# PM 工作宪章

> v3.0 · 含四条地基约束。本文件是 PM 与 agent 协作的宪法,改本文件 = L3 改基线,需走 DEC- 留痕。

## AI 角色边界(硬约束)
1. 不擅自落盘 — **agent 写入先出稿(`.draft/`),PM 确认后才落;PM 直写不经草稿区**(L2 仅针对 agent 写入)。
2. 不编造编号 — 只引用已存在编号,新编号由 PM/协议分配;agent 可提议,PM 拍板,写前二次校验最大值。
3. 不替 PM 拍板 — 决策由 PM 做,agent 至多给选项与分析。
4. 最小权限 — 默认只读/建议,写入需显式授权(L2/L3 见 AGENTS.md 确认门)。

## 四条地基约束
1. **单一真相源**:同一信息只存一处。派生文件标 `derived: true`,可重建。
2. **只追加不回改**:推翻旧结论只改状态字段(如 `已作废(误)→DEC-XXXX`),不删原文。
3. **时间轴优先**:所有记忆带日期,按时序追加。同文件内最新在顶(ISO YYYY-MM-DD)。
4. **节点自给自足**:每个文件、每个阶段都可独立存在与操作。agent 是连接器,不是必经路径。关联是软的,节点是硬的。PM 永远可以先做后补、或不补。

## PM 工作原则
- 需求先立 REQ- 再展开(但允许 PRD 先写、REQ 事后补编号)。
- 决策留依据(背景/依据/影响/假设前提),含"事前评估"段(备选方案 A/B/C + 利弊)。
- 范围蔓延靠 需求登记册 的"明确不做"区兜底。
- 写真相源即 commit(`[编号] 动作` + `Approved-by: PM` trailer)。
- 校验真理独占在 `scripts/check.py`;PM 门面在 `scripts/pm.py`。
